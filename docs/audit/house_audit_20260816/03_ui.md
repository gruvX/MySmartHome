## 1. Information architecture as-is

## 2. Coverage gap

Method: every `entity_id` literal in each source was extracted and cross-referenced against a
live `/api/states` snapshot (817 entities, taken 2026-08-16 14:xx). Tablet references **129**
distinct ids, the Mini App **107**. Of the 160 entities in genuinely controllable domains
(`switch, light, climate, script, scene, siren, vacuum, fan, humidifier, media_player,
input_boolean, water_heater`), **111 are reachable from neither surface** (69 %).

Many of those 111 are Tuya duplicates of something already exposed (`switch.boiler` vs
`switch.smart_plug_2_socket_1`, `switch.perekryt_vodu` vs `switch.voda_kran_switch_1`,
`switch.akvarium_svet` vs `..._socket_1`, plus 8 `*_child_lock` entities). Stripping those,
the **real** functional gaps are:

## 3. Duplication & inconsistency

### 3.1 Dead code

Method: iterative fixpoint — a function is dead if its name appears nowhere except its own
definition, the `Object.assign(window,…)` export line, and the bodies of other dead functions.
Repeat until stable. (A one-level scan finds only 35; the fixpoint finds the callers-of-dead-
callers too.)

**Tablet — 50 of 301 functions dead, 488 lines, 11.3 % of the file.**

Three whole generations of home screen are fossilised in the file at once:

| Fossil layer | Dead functions | Lines | What was lost |
|---|---|---|---|
| `homeCard*` (gen 1) | `homeCardUnavail` `homeCardWater` `homeCardTop3` `homeCardBatteries` `homeCardElectricity` `homeCardEnergyToday` `homeCardQuality` `homeCardClimate` `homeCardCost` `homeCardAutoProtect` `homeCardServer` `homeQualityBadge` `homeUpdatedMeta` | ~161 | per-card home layout |
| `*Luxe` (gen 2) | `statsLuxe` `roomsLuxe` `devicesLuxe` `securityLuxe` `climateLuxe` `lightsLuxe` `energyLuxe` `calendarLuxe` `heroChip` `miniStatus` | ~92 | the "luxury" home |
| calendar chain | `todayPanel` → `monthGrid` `dayAgenda` `calendarRow` `selectCalendarDay` `eventsForDay` `eventTimeLabel` `eventTitle` `shortEventTitle` `isAllDayEvent` `dateKey` `parseDateKey` | ~92 | **the whole calendar** |
| `homeDock` strip | `homeDock` → `modeBtn` `eveningMode` `movieMode` | ~15 | «Освещение вкл. всё» and «Медиа гостиная» buttons |
| advisory / audit | `decisionCards` `serviceAutoAudit` `importantRows` `criticalAutoStatus` `securitySummary` `dailyPriceRows` `c1qBadge` `heatMini` `toggleTheme` `pxUnavail` `qs` | ~128 | see below |

Three consequences worth naming:

1. **The calendar is fetched and thrown away.** `loadCalendarData()` still runs on *every*
   `refreshAll()` — it calls `HASS.callApi` per calendar entity and builds `CAL_EVENTS` +
   `CAL_MONTH_EVENTS` — but the only surviving consumer is a diagnostic text field in Settings
   (line 318, «N событий»). The month grid, the day agenda and the event rows are all dead.
   Network + CPU spent on every cycle for a feature the user cannot see.
2. **`decisionCards()` is dead** — the "what should I do about it" generator: leak → «Проверьте
   зону и перекройте кран», valve state unknown, EV Tuya quota error, cheapest window. It is
   the single most owner-useful function in the file and nothing calls it.
3. **`criticalAutoStatus()` is dead**, and with it the only check that the leak/security
   automations are actually enabled. The panel therefore cannot tell the owner "your leak
   automation is off" — a real historical failure mode in this house.

**Mini App — 5 of 90 functions dead, 30 lines, 2.7 %.** `renderCalendarMini`, `renderRadar`,
`greeting` are truly orphaned; `toggleLight`/`togglePlug` are live via `window.v8toggleLight` /
`v8togglePlug` in markup. The Mini App is an order of magnitude cleaner than the panel.

**Dead data wiring — `SCENE_IDS` (Mini App line 332).** Four extra lights (Аквариум, Стена,
Занавески, Лестница) are wired to paired momentary Tuya switches and handled in `lightSvc`
(line 531) — but the `lights` array built in `mapStates` (line 450) contains no `akv`/`wall`/
`cur`/`stair` key, so the branch is unreachable. Four lights the code knows how to control are
invisible to the user.

### 3.3 Same concept, contradictory behaviour
- **«Ночь» scene threshold.** Tablet `sceneGoodNight()` (line 3415) hard-codes
  `price<=0.04` and the scene's own description text says «только если электричество дешёвое
  (≤ 0.04 €/кВт·ч)». The live automation «🔥 Бойлер по Nord Pool» switched to **0.10** on
  2026-07-12. The tablet therefore states a threshold that is 2.5× lower than the one the house
  actually uses, and acts on it. The Mini App has no equivalent scene, so the two surfaces
  disagree by omission.
- **«Ушёл» exists twice with different semantics.** Tablet `awayMode()` (line 3416) =
  arm + `light.turn_off all`, behind a 2-tap confirm. Tablet *scene* «Ушёл» = `script.scene_away`.
  Mini App `act('away')` = per-light off + arm (no confirm), **and** `act('sceneAway')` =
  `script.scene_away`. Four code paths, three behaviours, one name.
- **«Дома»/`home`.** Tablet `homeMode()` and Mini App `act('home')` both just disarm — but the
  Mini App also registers `home` as a *tab id*, so `v8nav('home')` and `v8act('home')` are
  different things one character apart.
- **Confirmation contract is not uniform.** Tablet: `confirmAction()` = press-twice-within-2.6 s
  (a toast, no dialog) for охрана and awayMode; a real modal (`askScene`, `askWaterOpen`) for
  scenes and water. Mini App: a real modal for water, EV start and arming — but **no confirm at
  all** for `away`, `night`, `allLightsOff` or the boiler ТЭН. So arming the house is
  confirm-guarded in one app and not the other.
- **Refresh cadence differs and neither is stated to the user.** Tablet: `hass` push, throttled
  to 1.2 s, plus a periodic `refreshAll`. Mini App: poll, default 30 s, user-settable 10 s+.
- **Floor setpoint staging is duplicated verbatim.** `floorStepSp`/`floorApplySp`/`floorCancelSp`
  + `FLOOR_SP_MIN/MAX/STEP` clamping exists independently in both files. This is good design
  (stage, clamp twice, apply explicitly) implemented twice, so it can drift.

## 4. Honesty defects — what REMAINS

### 4.1 Confirmed FIXED (verified, not taken on trust)
- **Leak single source of truth.** Both surfaces derive leak/blind/dry from
  `sensor.leak_protection_status` only. Tablet: `LEAK_TRUTH`/`leakTruth()`/`leakVerdict()`
  (lines 216–252) with an explicit comment that the 4 moisture rows do **not** decide status.
  Mini App: `leakInfo()` / `LEAK_*`. No per-UI staleness heuristic remains. Holds.
- **Mini App demo price curve.** `mapStates` now gates on `pricesAreReal(payload)` and degrades
  to `NO_PRICES() = new Array(48).fill(null)` — explicitly **not** `app.data.price.arr`, which
  on a cold start would have been the demo curve (line 411 comment records exactly this).
  Verified for TODAY as well as «Завтра». Holds.
- **Tri-state everywhere in the Mini App.** `availOf()` + per-field `avail:{}` maps; the code
  refuses to act on an unreadable entity (`isAvail()` guard on boiler, valve, arming, floors)
  and prints «нет данных». This is genuinely well done.

### 4.2 REMAINING — ranked

**H1 (highest). The tablet paints a partly fabricated house on every boot — VERIFIED.**
`boot()` (line 4204) runs `loadDemo(); render(); refreshAll();` in that order.
`loadDemo()` (line 759) writes **70 invented entity states** straight into `S` — the same object
every renderer reads:

```
put('sensor.nord_pool_lv_current_price','0.034');  put('sensor.boiler_cwu_temperature','48.2');
SECURITY.forEach(x=>put(x[0],'off'));              // door «закрыта», smoke «норма», 4 moisture «off»
put('switch.voda_kran_switch_1','on'); put('input_boolean.security_armed','off'); put('siren.alarm','off');
```

`render()` paints all seven screens from that. Only then does `refreshAll()` run, and it
`await`s `/local/today_prices.json` **and** the calendar `callApi` before re-rendering — so the
browser does paint the fabricated frame, for as long as those two requests take.

**Measured, not inferred.** Rendered in the harness with the price fetch delayed to 5 s
(a degraded link — exactly when this matters). At t = 1.5 s the panel showed:

| Element | Displayed | Truth |
|---|---|---|
| `pricePill` | **0.034** | 0.006 |
| `miniBoiler` | **Догорание** | fabricated (real value coincidentally the same) |
| `miniWater` | **открыт** | fabricated |
| `armedPill` | **выкл** | fabricated |
| Дверь | **закрыта** | fabricated |
| Дым | **норма** | fabricated |
| Ванная / Гараж / Кухня / Душевая | «неизвестно» | *honest* |
| Контроль протечки | «Статус защиты неизвестен» | *honest* |
| `connState` | `demo` | correct |

Evidence: `ui_screens/EVIDENCE_tablet_boot_demo_frame.png`.

**The nuance matters and is good news.** The four leak rows and the protection verdict came out
**honest** — because `leakVerdict()` reads `sensor.leak_protection_status`, and `loadDemo()` does
not fabricate that entity. The leak single-source-of-truth work accidentally immunised the leak
display against this whole class of bug. That is the strongest possible argument for the pattern.

**What is still fabricated is everything the pattern does not cover**: the spot price, the boiler
mode, the main valve position, the armed state, **the door sensor and the smoke sensor** — the
last two shown as reassuring «закрыта» and «норма» when nothing has been read from the house.
A second entry to the same code is the `catch` in `refreshAll()` (line 566), which re-runs
`loadDemo()` whenever the HA session is unreadable and `S` is empty.

The only signal is the word `demo` in a small `connState` pill. *The Mini App has no equivalent
defect* — `mockData()` exists but `renderShell()` returns a loader while `app.auth !== "ok"`, and
`auth` only becomes `ok` after a successful fetch.

**Fix: delete `loadDemo()` and render «нет данных» until real state arrives** — or, if a
skeleton is wanted, extend the leak-truth pattern so no safety input can ever be fabricated.

**H2. Fabricated zeros in the Mini App boiler block.** `num(S,eid)` (line 210) is
`parseFloat(...)` with `isNaN ? 0`. `mapStates` uses it for eight readings:
`nord_pool_lv_current_price`, `cost_month_total`, `boiler_co_temperature`, `boiler_co_setpoint`,
`boiler_cwu_temperature`, `boiler_cwu_setpoint`, `boiler_return_temperature`, `boiler_fan_power`.
An unreadable boiler sensor becomes a confident **0 °C**. There *is* a `boiler.avail{}` map
alongside, so whether this surfaces depends on every consumer checking it — a guard that has to
be remembered at each of ~12 call sites rather than being structurally impossible. The ecoNET
boiler is the single flakiest device in this house (its WiFi drops; its IP has drifted
.10→.11→.12), so this is the most likely honesty defect to actually fire.

**H3. Staleness is marked on exactly one tile.** The Mini App sets `app.stale = true` when a
poll fails, but the only place it is rendered is the Nord Pool tile on «Главная» (line 711,
«данные устарели»). Every other panel — boiler temps, floor setpoints, security, energy, rooms —
keeps painting the last good snapshot with no age marker at all. A phone that lost connectivity
20 minutes ago shows 20-minute-old room temperatures and security state as current.
The tablet is better here: `ageMins()`/`c1oldestAge()`/`homeFreshLabel()` drive an «обновлено»
chip and a quality badge — but those cover only the **energy/price** ids
(`C1_PRICE.now` + device energy sensors). Security, climate and floor readouts carry no age.

**H4. `sceneGoodNight()` acts on a threshold the house abandoned.** Line 3415 hard-codes
`price<=0.04` and the scene description shown in the confirm modal says «≤ 0.04 €/кВт·ч».
The live automation uses **0.10** since 2026-07-12. The panel is telling the owner a false fact
about his own house and then acting on it.

**H5. `mapStates` returns `{...app.data, …}`.** Today every key is overwritten, so nothing
leaks. But the spread means any future key added to `mockData()` and not to `mapStates()`
silently becomes permanent fake data. A latent trap, not an active defect.

**H6. Leak *bypass* booleans are invisible.** `input_boolean.moisture_bypass_{vannaia,garazh,

«Безопасность» screen say «сухо / защита работает» while that zone is in fact unprotected.
This is a *true statement about the sensor* presented as a *false statement about protection*.

**H7. Public stale copies of the UI on `/local/`.** `/config/www/` still holds
`smarthouse.html.bak_20260727_leaktruth`, `smarthouse.html.bak_20260728_selfupdate` and
`tablet-panel.js.bak_20260727_leaktruth`. `/local/*` is served without auth. Anyone with the URL
gets a pre-fix Mini App — including the *pre-leak-truth* one, i.e. a UI with the honesty bugs
that were deliberately removed. Not a data leak (no tokens in them — verified), but they are
live, reachable, wrong-by-design copies.

## 5. Ergonomics — measured

Method: both surfaces rendered headless (Playwright + Chromium 151) against **live HA data**
(a real `/api/states` snapshot; the tablet harness feeds `hass.states` exactly as `panel_custom`
does, the Mini App harness stubs `/api/miniapp-auth|state|calendar` with the real
`STATE_IDS` subset the component would return, plus the real `/local/today_prices.json`).
Measurements are taken **per active screen**, walking into the shadow root. Screenshots of every
screen at every size are in `ui_screens/` (67 files).

### 5.4 Two further defects the render exposed

**E1 — the Mini App shows nothing about safety when safety is fine.**
`renderHome` emits the «Требуется внимание» panel only `if(a.length)` and the «Датчики
недоступны» panel only `if(!a.length && v.blind.length)`. With the house in its normal state
(verified live: `sensor.leak_protection_status = ok`) **neither renders**, so «Главная» carries
no safety information at all and no link to it — see `ui_screens/miniapp_390x844_home.png`.
For a household whose defining anxiety is water damage, the home screen answers "is my house
leaking?" only by saying nothing. Absence of an alarm is not visible assurance, and the owner
cannot distinguish "all dry" from "the panel isn't checking".

**E2 — the safety card cries stale because a kWh counter is old.**
`securityEmergencyCard()` line 3054 injects `homeFreshLabel()` into the security card as
«**Данные устарели.** … часть показателей может быть неактуальна». But `homeFreshLabel()`
(line 865) is computed **only** from `C1_PRICE.now` plus the six device *energy* counters —
it never looks at a single leak, door or smoke entity. In the live render
(`ui_screens/tablet_1280x800_security.png`) the banner fires because an energy counter is ~7 h
old, and it sits directly above six confident green badges and the sentence
«4 из 4 датчиков протечки **подтверждены** сухими». One card simultaneously warns that the
data may be wrong and asserts that the sensors are confirmed. Two harms: a false alarm on the
safety screen, and — worse — it teaches the owner to ignore the stale banner, so when the leak
data really *is* stale the warning is already noise.

## 7. Technical debt — what to rebuild, what to carry over

### 7.1 Size and structure

| | Tablet panel | Mini App |
|---|---|---|
| File | `tablet/tablet-panel.js` | `miniapp/smarthouse_v8.html` |
| Bytes / lines | 371 845 / 4 336 | 119 347 / 1 099 |
| Functions | 301 (**50 dead, 488 lines, 11.3 %**) | 90 (5 dead, 30 lines, 2.7 %) |
| CSS | **108 484 B = 29 % of the file**, in **6 stacked constants** | one 21 295 B `<style>` |
| Longest line | **75 064 chars** (`PANEL_CSS` as one string literal) | 1 948 chars |
| Markup | `PANEL_MARKUP`, a 12 532 B escaped string | template literals per view |
| Delivery | `panel_custom` → shadow DOM | single HTML file |
| State in | `hass.states` push (throttled 1.2 s) + periodic `refreshAll` | `POST /api/miniapp-state` poll, 30 s |
| Globals | `Object.assign(window, {…})` — one line, ~200 names | `window.v8act` / `v8nav` / 2 more |

**The tablet's CSS is the debt.** `PANEL_CSS` is a single 75 KB string literal on one line —
uneditable, undiffable, unlintable. On top of it sit five override layers applied in sequence at
mount: `C1_EXTRA_CSS + REDESIGN_CSS + PKG2_CSS + PKG3_CSS + FIX0727_CSS` (33 KB). Each is a
historical patch that never got folded back, so any style question has to be answered by reading
six files' worth of cascade in order. This alone justifies "rebuild, don't refactor" for the panel.

**Render architecture is the other debt.** `render()` calls **nine** `render*` functions and
rebuilds `innerHTML` for **all seven screens** on every cycle — including the six that are not
visible — then `paintIcons()` re-walks the tree and `ensureSentinels()` re-appends sentinels.
This runs on every `hass` push (throttled to 1.2 s) and on the refresh timer. It is why three
generations of dead card-builders could accumulate unnoticed: nothing ever fails loudly.

The Mini App's `renderShell()` also rebuilds the whole document, but it is 1/4 the size, has one
CSS block, keeps per-tab scroll positions in `app.scroll`, and its view functions are pure
string builders with a single dispatch table. **Its structure is worth keeping.**

### 7.2 Worth carrying over — the hard-won pieces

1. **Leak single source of truth.** `sensor.leak_protection_status` decides leak/blind/dry, in
   both surfaces, with the per-UI staleness heuristics deliberately removed and a comment saying
   so. Locked by `tests/test_leak_truth.py`. **Carry over unchanged, including the test.**
2. **The self-update poller (tablet lines 46–758; Mini App `upd` object).** This is the best code
   in the project. It fetches `/local/{tablet,miniapp}-version.json` (no-store, cache-busted),
   caps the body at 4 KB, rejects non-object JSON, and gates the reload on, in order: browser
   storage present → this exact build not already reloaded for (so a failed deploy cannot loop) →
   session cap of 3 reloads → **and then the incident guards**: never reload while
   `leakVerdict()==='leak'`, never while smoke is on, never while a modal is open, never within
   30 s of a user interaction, never on a hidden tab (with a `visibilitychange` retry).
   It surfaces status as two quiet read-only rows in Настройки, never a toast.
   **Carry over verbatim.** Guarded by `tests/test_panel_build_marker.py` /
   `tests/test_miniapp_build_marker.py`.
3. **The action-confirmation contract (Mini App `cmdVerified`).** Send → await the real backend
   response → re-read HA state up to 5× → only then claim success; and if the entity is not in
   the allow-listed payload, say «отправлено, проверить нельзя» rather than inventing either an
   error or a success. No optimistic UI anywhere. **This is the model; the tablet does not have
   it and should get it.** (Contrast `livemap.html`, which uses `.then(done,done)` and toasts
   success on failure — see `03_ui_embedded.md`.)
4. **Honest «нет данных» rendering (Mini App).** `availOf()` + per-block `avail:{}` maps, and
   every control refuses to act on an entity it cannot read (`isAvail()` guards on boiler, valve,
   arming, all four floor controls). Tri-state, never two-state. **Carry over the pattern and
   make it structural** — see H2: `num()` returning 0 is the one place it is bypassed.
5. **Staged setpoints.** `floorPending` / `floorStepSp` / `floorApplySp` with a TTL, clamped to
   5–45 °C on *both* the step and the send, and clamped again server-side in
   `miniapp_auth` (`CLIMATE_TEMP_MIN/MAX/STEP`). A stray tap can never change the floor.
   **Carry over — but implement it once, not twice.**
6. **The `/api/miniapp-*` auth contract** (`custom_components/miniapp_auth/__init__.py`, 695 lines):
   HMAC validation of Telegram `initData`, single-uid allowlist, `MAX_AGE` + future-skew bounds,
   replay cache, token-bucket rate limiter, 16 KB body cap, and per-domain **entity allowlists**
   (`LIGHT_ENTITIES`, `SWITCH_ENTITIES`, `INPUT_BOOLEANS`, `SCRIPT_ENTITIES`, `CLIMATE_ENTITIES`,
   `REST_COMMANDS`, `SHELL_COMMANDS`) with server-side clamping of climate temperature and an
   `hvac_mode` allowlist. No token ever reaches the client. **Carry over.**
   **One change required:** line 687 calls `hass.services.async_call(..., blocking=False)` with
   no `Context`, so Mini App actions are unattributable (§6.3). Pass a `Context(user_id=…)`.
7. **Confirm-before-danger + explain-the-consequence.** `askWaterOpen()` writes out what opening
   the main valve actually does and that the panel will wait for the valve's own confirmation.
   The Mini App's modals do the same. Keep the pattern; apply it uniformly (§3.3 — it is
   currently applied to some dangerous actions and not others).
8. **Tri-state safety vocabulary.** `isKnownBinary` / `isBlindSensor` / `triLabel` (tablet) and
   `SAFETY_IDS` + tri-state (Mini App): an unreadable safety input is neither normal nor alarming,
   it is «неизвестно». Keep.
9. **Ergonomic floor already achieved.** Zero touch targets under 44 px and zero WCAG-AA contrast
   failures on both surfaces at all five viewports. Whatever the rebuild does, do not regress this.
10. **The `_charness.html` + fake-`hass` render-test idea.** It exists (`tests/test_tablet_scroll_reachability.py`)
    but its `_cstates.js` fixture is a stale 2026-07-18 snapshot. Rebuild it to pull a live
    `/api/states` snapshot, and extend it to assert the §5 metrics as regressions.

### 7.3 Rebuild, do not port
- `PANEL_CSS` + the five override layers → one design-token stylesheet.
- `PANEL_MARKUP` as an escaped string → real markup.
- The `homeCard*` / `*Luxe` / `home-c1` triple fossil → one home screen.
- `render()`-everything-every-tick → render the active view only.
- `loadDemo()` → **delete outright** (H1). A panel with no data must say so, not invent a house.
- The calendar chain → decide: show it or stop fetching it. Today it does neither (§3.1).
- «Энергия» → split the control surface from the engineering report (§5.1 items 3–4).
- The `Тablet`/`MiniApp` HA users exist with zero refresh tokens (§6.1) — either give the panel
  its own least-privilege session or delete the accounts; today the wall panel runs as the owner.

### 7.4 Housekeeping found on the box
- `/config/www/*.bak_2026072[78]_*` — three stale, publicly reachable copies of the UIs (§4 H7).
- `/config/www/tablet.html` is now a 980 B redirect stub; the 167 KB monolith survives only as
  gitignored `tablet/tablet.html`. `tablet/design_source.html` is **1.15 MB** of dead design
