# Классика: корневая причина дефекта sidebar/переполнения на 1024px

Дата: 2026-07-18 · Режим: R0 анализ · Файл: `tablet/tablet-panel.js` (classic panel_custom) · Production не изменялся.
Скриншоты: `docs/audit/classic_sidebar_1024/` (`tablet_1024.png`, `tablet_1024_annotated.png`, + energy/security/control 1024/1280/1366).

## Корневая причина (измерено)

1. **Фиксированный sidebar.** Корневой контейнер:
   ```
   .app{ display:grid; grid-template-columns:240px minmax(0,1fr); overflow:hidden; }
   ```
   Sidebar жёстко 240px. При ширине окна **1024px** контентная колонка = 1024 − 240 = **784px**.

2. **Нет брейкпоинта в диапазоне ~901–1180px.** Правила сжатия sidebar/сеток есть только на `@media(max-width:900px | 820 | 760 | 700)` (там sidebar сворачивается/сетки реформируются). Частичные твики на 1100/1180/1200 не трогают ширину sidebar. Планшет SM-T595 в этой раскладке (и режим 1024) попадает в «мёртвую зону»: **полный 240px sidebar сохраняется, а контент ужат до 784px**, без сворачивания и без реформирования сеток.

3. **Desktop-сетки не влезают в 784px.** В контенте используются сетки, рассчитанные на широкую область: `repeat(12,minmax(0,1fr))`, график Nord Pool `repeat(48,1fr)`, отопление `repeat(5,minmax(0,138px))` (≈690px минимум + gaps + padding → у края 784px), `repeat(3,minmax(120px,1fr))`, карточки с `min-width` и `padding`. Сумма минимальных ширин + gaps + paddings у ряда карточек превышает 784px.

4. **`overflow:hidden` на `.app` режет, а не скроллит.** Из-за clipping вместо переноса/скролла правый край карточек и часть контента **обрезаются** на 1024 (видно на `tablet_1024_annotated.png`). Это и воспринимается владельцем как «дефект sidebar на 1024».

Итого: **fixed 240px sidebar + отсутствие брейкпоинта на 901–1180px + desktop-сетки + `overflow:hidden`** → на 1024 контент 784px, карточки не помещаются и обрезаются. На 1280/1366 контент 1040/1126px — терпимо, дефект не проявляется (подтверждается сравнением скриншотов).

## Минимальный фикс (предложение, НЕ применено)

Сохранить sidebar (как рекомендует $impeccable), но убрать «мёртвую зону»:

**Вариант A (рекомендуется) — компактный icon-rail на узких ширинах.**
```
@media (max-width:1180px){
  .app{ grid-template-columns:72px minmax(0,1fr); }      /* sidebar → icon-rail, +168px контенту */
  .sidebar .label{ display:none; }                        /* только иконки; подпись — title/aria-label */
}
```
На 1024 контент станет 952px вместо 784 — desktop-сетки помещаются без обрезания.

**Вариант B — реформировать 2–3 самые тесные сетки** на ≤1180px (12-кол→6, отопление 5→3-4, месячные приборы 3→2) вместо/в дополнение к сжатию sidebar.

**Обязательно к фиксу:**
- заменить на затронутых экранах `overflow:hidden` → корректный перенос/скролл внутри собственного контейнера, чтобы контент не резался;
- проверить `scrollWidth ≤ clientWidth` (нет горизонтального скролла) и отсутствие clipping на **1024/1280/1366**;
- сохранить touch-targets ≥44px и вторичный текст ≥12px (P1 impeccable) — при сжатии sidebar до icon-rail иконки должны остаться ≥44px и получить `aria-label`.

Точная карточка-виновник на 1024 отмечена в `tablet_1024_annotated.png`; фикс проверять именно на ней.
