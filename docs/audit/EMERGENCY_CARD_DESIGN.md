# Emergency / Security card — structure spec (classic design)

Дата: 2026-07-18
Режим: R0/R1 — **только дизайн-предложение**. Production (`tablet/tablet-panel.js`,
`miniapp/smarthouse_v8.html`) НЕ изменялся. HA читался только на чтение (снимок состояний
для реалистичных значений). Команды дому не отправлялись, секреты не печатались.

Основано на:
- критике `impeccable` (`.impeccable/critique/2026-07-17T21-13-02Z__…md`, раздел «Безопасность»):
  «Сохранить высокий визуальный приоритет. Норма должна занимать мало места; при проблеме блок
  расширяется и показывает **источник, время, фактическое состояние и безопасное действие**»;
- требовании владельца: **никогда не прятать аварийный смысл за «…»** — критический текст читается
  полностью, длинные подписи переносятся на несколько строк.

Артефакты:
- мок: `docs/audit/emergency_card_mock/index.html` (self-contained, `?state=normal|attention|critical|unavailable`)
- скриншоты: `docs/audit/emergency_card_mock/{normal,attention,critical,unavailable}_{1024,1280,1366}.png`

## 1. Что сохраняется из текущей логики (без ослабления)

Существующая семантика безопасности из `tablet-panel.js` остаётся источником истины. Дизайн — это
только новая **презентация** уже вычисленных уровней. Ключевые функции и правила:

| Функция (`tablet-panel.js`) | Правило, которое НЕЛЬЗЯ ослаблять |
|---|---|
| `waterStatus()` | Открытый кран сам по себе = **норма (green)**. Реальная течь ИЛИ слепой/устаревший датчик (`unavailable`/`unknown` или возраст >180 мин) = **red**. Кран `unknown` = yellow. Grace stuck-on (авто-закрытие отключено) = yellow. |
| `issues()` | RED-события: HA недоступен, задымление, вода-red, сирена, авария котла, дверь открыта при включённой охране. |
| `attentions()` | YELLOW: кран неизвестен, дверь открыта без охраны, EV quota_error, высокая цена, устаревшие данные. |
| `criticalAutoStatus()` | Защитные автоматизации: grace не сбросился → red; автоматизация протечки off/unavailable → red; статус неизвестен → yellow; дым-сирена off → yellow. |
| `askWaterOpen()` → `openWater()` | Открытие крана — единственное разрешённое из карточки управление; **gated: диалог подтверждения + описание последствий + read-back (успех только при фактическом `state==='on'`)**. |
| `closeWater()` | Аварийное закрытие — `confirmAction()` + read-back до `state==='off'`. |

Дизайн НЕ меняет эти вычисления и НЕ добавляет новых команд. `open valve = normal`, `blind/stale
sensor = red`, `water-open = confirm+read-back` сохраняются дословно.

### Найденный источник «…» (что нужно исключить)

В текущем рендере датчики выводятся строкой `.signal`:

```css
.signal b{font-size:13px;white-space:nowrap;overflow:hidden;text-overflow:ellipsis}
```

`renderSecurity()`, `securitySummary()`, `homeCardWater()` печатают критический текст через
`sensorRow()`/`c1row()`, то есть внутри `.signal` → при нехватке ширины подпись и «detail»
обрезаются многоточием. **Новая аварийная карточка не должна использовать `.signal` для
критического текста.** Она использует собственные классы `.emg-*`, где текст переносится.

## 2. Четыре состояния карточки

Карточка `.emg` имеет постоянную «шапку» (щит + «Безопасность» + бейдж уровня + счётчик событий)
и тело, которое меняется по уровню. Слева — цветной вертикальный «рельс» (единственный сильный
визуальный сигнал приоритета): green / amber / red / серый (unknown).

### 2.1 NORMAL (green) — компактно, спокойно

- Одна строка-заверение: «Всё в норме · дом под наблюдением» + галочка.
- Компактный ряд **не-кликабельных** чипов-статусов: Охрана, Дверь, Дым, Главный кран
  (открыт — нормальный режим), Датчики протечки (N · сухо), Автозащита.
- Действий нет. Минимальная высота. Ничего значимого не скрыто — просто нечего показывать.

### 2.2 ATTENTION (yellow) — короткие, полностью читаемые строки

- Бейдж «внимание · N».
- Каждая проблема — отдельная янтарная строка с иконкой и **переносимым** текстом, например:
  «Дверь открыта. Охрана снята — это не тревога, но дверь стоит закрыть…» /
  «Состояние крана неизвестно. Нет подтверждения от Tuya…».
- Внизу компактная строка «Остальное в норме: …».
- Опасные действия НЕ разворачиваются на этом уровне (нет течи/дыма).

### 2.3 CRITICAL (red) — карточка РАСШИРЯЕТСЯ

Бейдж «ТРЕВОГА · N события». Для **каждого** инцидента — блок `.emg-incident` с красным
контуром и пятью подписанными полями (grid `label | value`, всё переносится):

1. **ЧТО СЛУЧИЛОСЬ** — тип события человеческим языком («Протечка воды», «Задымление»,
   «Кран не подтвердил закрытие», «Авария котла», «Охрана: дверь открыта»).
2. **ИСТОЧНИК** — конкретный датчик + комната + `entity_id` (моноширинный, переносится через
   `overflow-wrap:anywhere`): «Датчик «Кухня» · `binary_sensor.kukhnia_moisture` (под мойкой)».
3. **КОГДА** — «Сработал 2 мин назад · сегодня в 09:32» (из `last_updated` через `ageMins()`/`c1age()`).
4. **ФАКТИЧЕСКОЕ СОСТОЯНИЕ (read-back)** — реальное состояние исполнительного устройства,
   прочитанное из HA: «Главный кран: **ОТКРЫТ** — вода подаётся на весь дом (подтверждено от Tuya,
   `switch.voda_kran_switch_1 = on`)». Именно фактическое чтение, а не намерение.
5. **БЕЗОПАСНОЕ ДЕЙСТВИЕ (gated)** — крупная кнопка ≥44px + пояснение gate: «спросит
   подтверждение, дождётся фактического подтверждения от крана, покажет успех только когда кран
   реально закрыт» (= существующий `closeWater()`/`openWater()` read-back).

Инциденты **стекаются** (мок показывает течь + задымление сразу). Полный список НЕ усечён (в
отличие от `problem.slice(0,3)` в hero/state-line — там усечение допустимо, в карточке нет).

### 2.4 UNAVAILABLE / UNKNOWN — «НЕ безопасно», отдельная сигнатура

Недоступный или устаревший **защитный** датчик по действующей семантике = red-уровень (слепая
защита), но рисуется с **отдельным визуальным кодом**, чтобы не путать с подтверждённой тревогой
и не выдать за норму:

- Бейдж «НЕ БЕЗОПАСНО · датчики недоступны», серый рельс, штриховка фона инцидента.
- Поля те же (ЧТО/ИСТОЧНИК/КОГДА/ФАКТ), но состояние показывается как **«недоступен»**,
  **«устарел: последнее обновление 5 ч назад (порог 3 ч)»**, **«неизвестно»** — курсивом, серым.
  Никогда `зелёный`, никогда `0`, никогда «закрыт», если фактически `unavailable`.
- Блок **«ЧТО ПРОВЕРИТЬ»**: питание/Wi-Fi датчика, связь Tuya, обновить состояния.
- Чипы прочих датчиков: подтверждённые — зелёные; недоступные/устаревшие — **серые пунктирные**
  «неизвестно», а не зелёные «сухо».
- Безопасное действие остаётся доступным (аварийно закрыть кран вручную, gated), т.к. пока
  датчики слепы — безопаснее перекрыть воду.

## 3. Правило «никаких многоточий» (no-ellipsis)

Реализовано на уровне CSS-гарантии для всего поддерева карточки:

```css
.emg, .emg *{ overflow-wrap:anywhere; word-break:normal; }  /* длинные entity_id ломаются на строку */
.emg [class]{ text-overflow:clip; }                          /* глиф «…» не рендерится никогда */
```

Плюс структурные правила:

- Аварийный текст НЕ выводится через `.signal` (единственный класс с `text-overflow:ellipsis`).
- Ни на одном контейнере критического текста нет пары `max-width` + `overflow:hidden`, нет
  `white-space:nowrap`, нет `-webkit-line-clamp`.
- Значения-поля (`.emg-field .v`), кнопки (`.emg-btn`), чипы (`.emg-chip`), бейдж уровня
  (`.emg-lvbadge`) — все `white-space:normal` и переносятся на нужное число строк.
- Длинные `entity_id` (моноширинные) специально включены в мок как стресс-тест: они переносятся,
  а не выходят за карточку.

Проверка автоматизирована в скрипте съёмки (см. §5): для каждого из 12 рендеров проверяется, что
в видимом тексте карточки **нет символа U+2026 «…»**, нет элементов с активным
`text-overflow:ellipsis`, нет обрезанных (`overflow:hidden` + переполнение) листовых узлов.

## 4. Маппинг на существующие сущности и логику

| Поле карточки | Источник (существующий код / entity) |
|---|---|
| Уровень (рельс/бейдж) | `issues().length?red : attentions().length?yellow : green`; слепой датчик → `waterStatus().level==='red'` |
| Инцидент «Протечка» | `waterStatus()` leaks (`binary_sensor.{vannaia,garazh,kukhnia,water_sensor_4}_moisture` == on) |
| Инцидент «Датчик недоступен» | `waterStatus()` blind (`unavailable`/`unknown` или `ageMins>180`) |
| Инцидент «Задымление» | `binary_sensor.wifi_th_smoke_sensor_smoke` == on |
| Инцидент «Сирена» | `siren.alarm` == on |
| Инцидент «Авария котла» | `sensor.boiler_mode` == 'Авария' |
| Инцидент «Дверь + охрана» | `binary_sensor.door_sensor_door` on && `input_boolean.security_armed` on |
| Attention «Дверь без охраны» | door on && armed off |
| Attention «Кран неизвестен» | `switch.voda_kran_switch_1` ∉ {on,off} |
| Attention «Авто-закрытие отключено» | `input_boolean.ha_startup_grace` on (`criticalAutoStatus`) |
| ИСТОЧНИК (датчик+комната+id) | `SECURITY[]` (label в `x[1]`, entity в `x[0]`) |
| КОГДА | `ageMins(entity)` / `c1age(S, entity)` из `last_updated` |
| ФАКТ / read-back (кран) | `st('switch.voda_kran_switch_1')` — реальное состояние, `human()`/явное «неизвестно» |
| Безопасное действие «Закрыть» | `closeWater()` — `confirmAction()` + read-back до `off` |
| Безопасное действие «Открыть» | `askWaterOpen()`→`openWater()` — модал подтверждения + read-back до `on` |
| Безопасное действие «Сирена» | `silenceSiren()` |
| Чип «неизвестно» (не «0») | `st()==='unavailable'||'unknown'` → серый пунктир, `c1nd()` семантика («нет данных», курсив) |

Никаких новых entity, сервисов или порогов. Все значения читаются теми же геттерами
(`st`, `isOn`, `num`, `attr`, `ageMins`).

## 5. Проверка (headless)

Скрипт рендерит мок в chromium при 1024×768, 1280×800, 1366×768 для всех 4 состояний (12 PNG,
`device_scale_factor=1`, full-page). Для каждого рендера проверено программно:

- горизонтальный скролл страницы = 0;
- нет элементов шире контейнера (`scrollWidth>clientWidth`) → нет переполнения/перекрытия;
- нет активного `text-overflow:ellipsis` и нет обрезанных листовых узлов;
- нет символа «…» (U+2026) в видимом тексте карточки.

Результат: **все 12 рендеров прошли все проверки** (0 hscroll, 0 overflow, 0 clip, ellipsisChar=False).
