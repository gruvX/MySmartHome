# Proxmox — гости без реальных метрик диска (qemu-guest-agent)

_Агент: server-graphs-agent · Дата: 2026-07-17 · Репозиторий: `/home/user/projects/MySmartHome`_
_Режим: READ-ONLY. Это ПРЕДЛОЖЕНИЕ для владельца. Ничего не устанавливалось, VM/узел не менялись, Proxmox-API не вызывался, секреты/IP не раскрываются._

## 1. Суть проблемы

Интеграция `proxmoxve` в Home Assistant для каждой VM публикует сенсор
`sensor.<vm>_disk_usage`. Реальное **использование** диска изнутри гостя Proxmox
знает только через **qemu-guest-agent** (агент внутри гостевой ОС). Если агент не
установлен или не включён — Proxmox отдаёт `0`, и HA показывает `0.0 GiB`.
`sensor.<vm>_max_disk_usage` (выделенный размер) при этом корректен.

Поэтому на экране «Server» использование диска **гостей** сознательно не
показывается как число (только пометка «использование диска гостей недоступно
(нет guest agent)»), а графики/прогноз заполнения строятся **только по
хранилищам узла** (`storage_*`), где данные достоверны.

## 2. Кто сейчас отдаёт 0 (нужен агент)

Все 6 VM сообщают `disk_used = 0.0 GiB` (по инвентаризации `proxmox_inventory.json`).

| VMID | Имя | Статус | disk_used / max | Нужен qemu-guest-agent? |
|---|---|---|---|---|
| 100 | homelab-staging | running | 0.0 / 40 GiB | **ДА** — running, метрика нулевая |
| 101 | homelab-dev | running | 0.0 / 60 GiB | **ДА** |
| 102 | ssh-tool | running | 0.0 / 20 GiB | **ДА** |
| 200 | homeassistant | running | 0.0 / 32 GiB | **ДА** (особый случай — см. §4, HAOS) |
| 9001 | homelab-ci-runner | running | 0.0 / 120 GiB | **ДА** |
| 9000 | homelab-clean-ubuntu-2404 | stopped | 0.0 / 80 GiB | Проверить после запуска (0 у остановленной VM — норма) |

**Итог:** реальное использование диска отсутствует у всех VM. Для 5 работающих VM
это точно из-за агента; для остановленной 9000 значение 0 ожидаемо — оценивать
только когда она запущена.

Замечание: LXC-контейнеров нет (все гости — VM), поэтому пункт про агент касается
только VM. У LXC использование диска Proxmox знает и без guest-agent.

## 3. Что даёт установка агента (кроме диска)

- достоверное **использование диска** VM (появится в `sensor.<vm>_disk_usage`),
  что откроет графики/прогноз заполнения и для гостей, а не только для хранилищ;
- корректный **fs-freeze** при снапшотах/бэкапах (консистентные снимки);
- корректное **graceful shutdown/reboot** через Proxmox;
- IP-адреса гостя в UI Proxmox.

Риск минимален (пакет + включение опции). Но это изменение **внутри гостей** —
уровень R2, выполняется владельцем, вне задач этого агента.

## 4. Инструкция владельцу (ПРЕДЛОЖЕНИЕ — не выполнять автоматически)

Для КАЖДОЙ VM нужно (a) включить опцию агента в Proxmox и (b) установить агент в
гостевой ОС. Только оба шага вместе дают метрики.

### Шаг A — включить в Proxmox (для каждой VM)
`Datacenter → mylab → <VM> → Options → QEMU Guest Agent → Enabled` (галочка `Use
QEMU Guest Agent`). Изменение применяется после **полного выключения и запуска**
VM (не «reboot» из гостя — нужен цикл off/on, чтобы подцепился виртуальный
последовательный канал агента). CLI-эквивалент (на узле): `qm set <vmid> --agent
enabled=1` — приводится только как справка, **выполняет владелец**.

### Шаг B — установить агента в гостевой ОС

**Ubuntu / Debian (homelab-staging, homelab-dev, homelab-ci-runner, ssh-tool,
базовый образ 9000)** — вероятно Ubuntu 24.04 по имени `...-ubuntu-2404`:
```
sudo apt update
sudo apt install -y qemu-guest-agent
sudo systemctl enable --now qemu-guest-agent
```

**Совет по базовому образу:** установить агент один раз в шаблоне
`homelab-clean-ubuntu-2404` (VMID 9000) — тогда новые VM из него уже будут с
агентом, отдельно ставить не придётся.

**Home Assistant OS (VM 200 `homeassistant`)** — особый случай:
- HAOS — это управляемый образ; `apt` там нет. В современных сборках HAOS
  qemu-guest-agent идёт как часть ОС и включается автоматически при включённой
  опции в Proxmox (Шаг A) + цикле off/on.
- Если после Шага A диск всё ещё `0` — обновить HAOS до актуальной версии и
  проверить, что в Proxmox выбран тип гостя Linux. Ставить пакеты внутрь HAOS
  вручную **не следует** (неподдерживаемо).
- Отдельно уточнить: является ли VM 200 тем же инстансом HA, что опрашивается в
  этом проекте, — по инвентаризации это **не подтверждено** (§6 PROXMOX_INVENTORY.md).

**ssh-tool (VM 102)** — ОС не подтверждена. Если это Debian/Ubuntu — команды выше;
если иное (Alpine: `apk add qemu-guest-agent`; RHEL/Alma/Rocky:
`dnf install qemu-guest-agent`). Определить ОС перед установкой.

### Шаг C — проверка (read-only)
После off/on: в Proxmox на странице VM пропадёт предупреждение «Guest Agent not
running», появятся IP гостя. В Home Assistant через ~1–2 цикла опроса
`sensor.<vm>_disk_usage` станет ненулевым; на экране «Server» у гостей появится
реальное использование диска (доработку отображения по гостям делать отдельной
задачей — сейчас панель для гостей диск не показывает намеренно).

## 5. Границы этого предложения

- Это только список и инструкция. Установка/включение агента, off/on VM — **R2,
  делает владелец**. Данный агент ничего не менял и не запускал.
- Панель «Server» остаётся строго read-only: она лишь читает сенсоры и историю
  (recorder) и не управляет ни узлом, ни VM.
