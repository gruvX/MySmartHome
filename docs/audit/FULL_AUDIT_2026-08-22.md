# MySmartHome — полный аудит на 2026-08-22

Режим: `AUDIT`, риск R0. Репозиторий, Home Assistant, устройства и внешние
сервисы не изменялись. Физические команды воде, отоплению, охране, EV и силовым
розеткам не отправлялись.

## Итог

Активной аварии нет. Home Assistant работает, защита воды сообщает `ok`, четыре
датчика протечки сухие и доступны, startup grace и bypass выключены, кран открыт,
сирена выключена. Котёл, Nord Pool и узел Proxmox на момент проверки доступны.

Главные незакрытые риски:

1. **HIGH — эпизодические отказы Tuya-команд.** Ошибки подписи/remote API 21 августа
   прервали реальный EV/бойлер interlock и применение ночной экономии. Self-heal
   снижает последствия, но не доказывает выполнение команды.
2. **HIGH — Mini App backend допускает обход frontend-защит.** Production auth
   использует окно Telegram `initData` 24 часа и не содержит подготовленных локально
   body/rate/future-date ограничений. Критические действия вызываются неблокирующим
   service-call и получают `ok` без backend read-back; UI confirm можно обойти прямым
   запросом с действительным `initData`.
3. **HIGH — активный boiler credential размножен по локальным snapshot.** 56 копий
   в семи ignored-файлах с правами `0644`. Git и Git history чисты, но P0-критерий
   минимальной at-rest экспозиции снова нарушен.
4. **HIGH — production не воспроизводим из Git.** EV scheduler-скрипты в HA не имеют
   точного локального соответствия и значительно расходятся с tracked-версиями.
   Основные августовские production-источники и тесты остаются untracked; HEAD всё ещё
   от 21 июля.

## Подсистемы

### Home Assistant и автоматизации

- 848 текущих entities; 72 automation, из них 68 включены и 4 выключены;
  unavailable automation нет; ID в production уникальны.
- Утренний Telegram briefing не доставляется три дня подряд из-за ошибки Telegram
  `Can't parse entities`.
- Рециркуляционная розетка и её power/current/energy недоступны; расписание выключено.
  Не установлено, намеренно ли устройство выведено из эксплуатации.
- Облачный резерв проверки протечки имеет состояние `unknown`; четыре прямых датчика
  и агрегированный статус защиты сейчас исправны.
- Два охранных дверных датчика остаются недоступными. Низкий заряд: один пульт около
  20%, датчик гостиной около 23%.
- Пять старых Proxmox watchdog сосуществуют с объединённым watchdog, поэтому возможны
  дубли уведомлений. Узел и актуальный backup доступны; остановленную CI VM нужно
  классифицировать как штатную или аварийную.
- Xiaomi Home продолжает выдавать предупреждения о будущей несовместимости HA 2027.x.
- `ha core check` не подтверждён: CLI в read-only SSH-сессии не получил Supervisor auth.

### Энергетика

- Production стоимость остаётся старой helper-моделью шести нагрузок; whole-home
  meter отсутствует, интервальной production БД нет.
- Shadow collector пишет 15-минутные данные штатно, но пока является только evidence
  stream, а не официальным источником стоимости.
- Рециркуляция недоступна; TV/backlight meters плоские или мёртвые; поэтому полный
  баланс дома и «неучтённое потребление» вычислить нельзя.
- Nord Pool и файл текущего дня свежие. Отсутствие цен следующего дня утром является
  нормальным состоянием до публикации.

### Security и credentials

- Tracked HEAD: 0 секретов; staged: 0; Git history: 876 blobs, 0 находок.
- Secret stores и SSH key имеют права `0600`; web-root не содержит обнаруженных JWT,
  private keys, bot token или boiler password.
- В `/config/www` остаются восемь backup-артефактов; как минимум выборочные файлы
  публично доступны без авторизации. Очевидных секретов нет, но политика проекта
  запрещает backup в web-root.
- `ha_ssh.py` использует `AutoAddPolicy`, передаёт sudo password через командную строку
  и не гарантирует очистку временного upload.
- Scanner не покрывает архивы, изображения и файлы более 5 MB. Защищённый HA archive
  около 102 MB не был раскрыт и проверен по содержимому.

### Планшет и Mini App

Общая оценка UX/a11y: **13/20**. Production-файлы планшета v2, classic и Mini App
байт-в-байт совпадают с текущими локальными файлами.

- Пульт v2 помещается без горизонтального overflow и имеет touch-targets не меньше
  44 px, но 93 из 270 комбинаций экран/тема/размер обрезают значимые строки.
- На 1024 px особенно опасно обрезаются названия похожих watchdog/automation и
  provenance безопасности. Safety-текст нельзя оставлять с ellipsis.
- Экран Energy имеет оси, но при отсутствии массива цен оставляет чрезмерно большую
  пустую область вместо компактного объяснения причины и времени обновления.
- Mini App прокручивается до последнего элемента; unavailable не показывается как
  безопасное состояние; Nord Pool имеет X/Y оси.
- В Climate есть подписи 11–11.5 px и длинные строки с обрезанием.
- Пульт v2 и Mini App выглядят как два разных продукта: светлый editorial/luxury против
  тёмного glow-интерфейса. Декоративные эффекты добавляют визуальный шум и стоимость
  рендера.
- Полное WCAG-соответствие не заявляется: contrast-run и проверка на физическом
  планшете/Telegram WebView не выполнены.

Свежие evidence находятся в `docs/audit/full_audit_20260822/frontend/`.

## Приоритетный план

### P0/P1 — следующий пакет

1. Локально спроектировать action-specific backend transaction для воды, охраны, EV и
   отопления: короткий nonce/session, строгая схема `extra`, blocking service-call,
   read-back и честный timeout. До этого не деплоить просто текущий auth-hardening.
2. Разобрать Tuya failure paths: команды должны завершаться только после read-back;
   при `sign invalid` сохранять последнее подтверждённое состояние и слать один alert,
   а не продолжать зависимую цепочку.
3. Исправить Telegram morning briefing и добавить render-test на реальном тексте.
4. Карантинировать/санитизировать семь snapshot с активным boiler credential и убрать
   backup из web-root. Это R2; ротация пароля при необходимости — отдельный R3.
5. Снять обезличенную production-копию EV scheduler, выбрать source of truth, перенести
   изменения в Git и только после этого принимать дальнейшие EV-правки.

### P2

6. Решить судьбу рециркуляции, дверных датчиков и остановленной CI VM с владельцем.
7. Сделать contract test строгим, добавить schemas для service/extra и покрыть
   entity-less commands.
8. Исправить SSH host-key verification и безопасную передачу/очистку временных файлов.
9. UI: убрать ellipsis у automation/safety provenance, поднять мелкие подписи,
   переработать пустой Energy state и унифицировать визуальные токены двух интерфейсов.
10. Энергетика: продолжать shadow, но не объявлять полный счёт до whole-home meter и
    подтверждённой интервальной production-модели.
